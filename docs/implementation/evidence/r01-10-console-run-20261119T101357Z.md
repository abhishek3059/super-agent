## Findings (not fixed here)

Later status: findings 1 (message), 3 and 4 were fixed in
[PR 57](https://github.com/abhishek3059/super-agent/pull/57). The muted and
stalled-microphone causes behind finding 1 are R-01.F10
([record](../r01-f10-idle-keepalive.md)).

1. **Idle timeout reads as a failure.** At 10:46Z the live session ended with "Voice session failed: session-timeout" and state "Needs attention", after about 3.5 min connected. The backend ends a session after 60 s with no incoming frames (`idle_timeout_seconds = 60` in `apps/api/src/super_agent_voice/config.py`, watchdog in `app.py`). The console appears not to send frames during silence, so a quiet pause counts as idle. The limit is by design, but the message reads as an error, not "ended after 60 s idle".
2. **Shared launcher venv was broken** before this run (pip and pydantic failed to import). The agent rebuilt it from `requirements.lock`. The cause was not checked.
3. **Operator feedback, console UX:** the session timer keeps running while muted and after speech stops. The operator asks to remove the timer or make it accurate.
4. **Operator feedback, token entry:** the local token must be pasted on every connect. The page is reviewed as memory-only for the token (REQ-11, REQ-12), so saving it in the browser would need a design change. One option that keeps the boundary is for the launcher to copy the token to the clipboard.
5. Chrome DevTools showed 2 console errors and 3 warnings during the operator part. Their content was not read.
